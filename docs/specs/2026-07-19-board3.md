## Iteration 3 (Ryan review round 3)

- **Concept fix — "boundary" → "sharing".** A **brain** is where a task lives (one owner,
  one brain per task; default `main`); a **sharing rule** is an audience grant (who can see
  a slice). The rail now lists ONLY places (My brains / Peers / Org); sharing is never a
  rail section — it lives in the brains manager + the task detail ("Shared with: jpark,
  org"). A one-liner ships in the UI: *Brains organize · sharing grants visibility ·
  promotion copies a curated version to the org brain.* Feed field `boundaries`→`shares`;
  feed **`schema: 3`** (adds `brain`, `shares`, `category.key`).
- **Brains & sharing config (real persistence).** New `lib/brains.py` + `task-station
  brains` subcommand family persists to **`<data_dir>/brains.json`** — a NEW additive file
  that NEVER touches `tasks.db` (task→brain assignment is a uuid→brain map kept there).
  Actions: `list · add · rename · archive · share --with <alias|org> [--tag] · unshare ·
  assign <task-ref> <brain> · show`. The exporter reads brains.json and resolves each self
  task's `brain` + `shares` (tag-scoped rules match the task's category tag).
- **Brains manager panel (view + edit).** Rail's "⚙ Manage brains" opens a house-style
  modal: my brains with task counts, create/rename/archive, per-brain audience chips
  (peers + org), and task reassignment via the row/node **✎ Move to brain…** action. A
  static `file://` page CANNOT write, so **every edit stages into the pending-changes tray**
  and **Apply emits the exact `task-station brains …` commands in a copyable block** (with a
  "copied ✓" affordance and an honest "changes apply via CLI — paste in any terminal" note).
- **Full filter parity.** Ported the real board's `_filters` row (search + category +
  status + session-state + reset, matching markup/classes) plus an effort dropdown; all wired
  to BOTH the table and the graph, composing with the rail mounts.
- **BOARD3-PARITY.md** — the honest real-board-vs-board3 checklist, enumerated from
  `render_board.py`'s section builders. The switchover gate. *(Deleted in #444 when the
  preview was retired; what became of it is recorded in
  [BOARD-RETIREMENT.md](BOARD-RETIREMENT.md).)*

## What changed from board2

| board2 | board3 |
|---|---|
| custom shell CSS | **imports `render_board._css()`** (+ a small board3 layer); rows reuse `.board/.row/.rowsum/.pill/.tag/.sec` so they're indistinguishable from real-board rows |
| three tabbed views (list / 2D / 3D) | **table + graph on ONE page**; the mounts rail drives BOTH; no tabs |
| board2's own graph | **ports the real board's `_MG_ENHANCE_JS`** (physics, camera, fit-view, zoom caps, `focal=560`, the 2D/3D toggle) + galaxy/blob/curve extensions |
| convex hulls | **smooth rounded blobs** (quadratic-midpoint closed spline; 3D = soft owner halos) |
| straight edges | **curved cross-galaxy edges** (quadratic arcs); memo pulses ride the curve |
| actions on nodes only | **actions on table rows AND graph nodes AND a global tray**, one shared staging state |
| `board2` subcommand / `lib/board2.py` / `tools/board2_shell.py` | `board3` / `lib/board3.py` / `tools/board3_shell.py`; feed `schema: 2` (added `category.key`) |

## Command

```
python3 lib/task-station.py board3 [--no-demo] [--no-open]
```

writes `<data_dir>/board3/` (`index.html`, `board3.rev.js`, `feeds/self.js`,
`feeds/self-archive.js`, `feeds/demo/*.js`) and opens it. Read-only: never mutates the
store (no `ensure_seqs()`; handle falls back to `rnguyen-<uuid8>` when a task has no seq).

## House style (reused, not reimplemented)

`lib/board3.py` / `tools/board3_shell.py` import `render_board` and call, WITHOUT
modifying it:

- `render_board._css(default_variant, render_board._category_css(synthetic, theme))`
  → the base stylesheet (palette vars, `.board/.row/.rowsum/.head/.pill/.tag/.sec/.sech`
  grid + component rules). `synthetic = [{"color": k} for k in the 12 category keys]` so
  every `.cat-<key>` rule exists for self AND demo rows.
- `render_board._theme_init_script(default_variant)` → the first-paint theme script
  (sets `html[data-theme]`/`[data-perf]` from `localStorage`; keys `ts-board-theme` /
  `ts-board-perf`, shared with the real board).

On top, a small `_CSS3` layer styles the new native-looking elements (mounts rail, owner
chips, handle column, tokens column, action cluster, galaxy graph panel, staging tray)
using the same palette vars, radius (6–12px), and spacing vocabulary. Rows carry the
real board's classes + `cat-<key>` + `stat-<display>` + `id="row-<uuid8>"`; the status
pill (● ◐ ○ ✕), category tag, and effort ▰▰▰ gauge match the house glyphs. A graceful
`_FALLBACK_CSS` keeps the board usable if `render_board` isn't importable.

## Same page: table + galaxy graph, one filter source

- **Left rail** = mounts (My brains / Peers / Org) + Boundaries. Toggling a mount
  shows/hides that owner's tasks in BOTH the table and the graph.
- **Search** (`#board-search`) filters both surfaces.
- **Table**: Active + Closed `.sec` sections of house-style rows (owner chip · handle ·
  task · category · effort · tokens · activity · action cluster). Closed lazily loads
  the archive shard ("show older"). Each row's expanded detail has the copied **View in
  graph** chip (`.mgviewbtn[data-graph-uuid]`) → focuses the node.
- **Graph → table**: clicking a node scrolls to `#row-<uuid8>` and flash-highlights it.

## Graph — ported engine + galaxy extensions

Ported from `_MG_ENHANCE_JS` (reimplemented cleanly, same constants): repulsion
`90000·SPREAD²/d²/d`, spring stiffness `0.04`, damping `0.9`, integrate `v·0.5·alpha`,
alpha cool `0.992`, momentum decay `0.94`, `focal=560`, orbit `0.01`/px, pitch clamp
`±1.3`, wheel `0.92/1.08`, auto-rotate `0.0022`. **One canvas, a 2D/3D toggle** (2D and
3D are the same graph, different projection). `fitView()` recenters the centroid and
fits both axes with the original zoom caps (`ZMIN=max(0.05, base·0.5)`,
`ZMAX=max(2.6, base·6)`) — so switching to 3D frames all galaxies and you start OUTSIDE
the scene, never inside a node field.

Extensions for multi-owner:

- **Galaxies**: per-owner gravity wells laid out on a ring around the origin (self first
  at −90°; in 3D the wells spread in the x/z plane with alternating y-tilt, like the
  original hub anchors). Nodes attract to their owner's well (`0.02`); a gentle global
  centering (`0.0012`) keeps the whole field bounded. **Org-shared nodes feel BOTH their
  owner's well and the org well** (`0.012`, = the `org` galaxy when mounted) so they sit
  BETWEEN their galaxy and the org — the visual of dual membership.
- **Smooth boundary blobs**: per-owner translucent rounded blob via a quadratic-midpoint
  closed spline through the padded convex hull (no pointy corners); the org blob is
  larger and drawn under, enclosing org-shared nodes across galaxies. 3D uses soft
  owner-colored halo spheres. Toggle in the legend.
- **Curved edges**: cross-galaxy edges (different owner) are quadratic arcs; within-galaxy
  edges stay straight. Dashed = cross-brain (shared PR/story), solid = within-brain,
  amber/gray directional pulse = memo (rides the curve). Token-log node sizing
  `r = clamp(7 + 11·log10(max(tok,5e5)/5e5), 7, 42)` with a 500k/5M/50M legend; two-color
  split ring for multi-participant nodes; owner colors (CVD set, always with the alias).

## Actions everywhere + shared staging

The four actions — **⇡ Promote to org · ⇢ Share to boundary… · ✉ Send memo · ✎ Edit** —
are reachable from every surface: the table row's end-of-row action cluster, the graph
node's hover-card buttons (selection works in 2D and 3D), and the global slide-in tray.
All read/write ONE shared state (`window.__B3.SEL` selections + `window.__B3.STAGE`
staged actions), so a staged badge (⇡/⇢/✉) shows in the table AND on the graph node
simultaneously. **Foreign nodes: only ✉ memo is enabled**; Promote/Share/Edit are
`disabled` (not hidden) with a "read-only · foreign brain" tooltip — teaching the model.
Apply(n)/Discard are stubs that clear the staged badges (instant under reduced-motion).

## What's real vs stubbed

Real: self feed (store → read-only view-model), tokens/cost/models (usage ledger join,
est-zero fallback), liveness (self only), archive shard, cross-brain edges + memo pulses
to real tasks (seed rewrites sentinels), house style. Stubbed: pending-changes actions
(staged badges, no store writes), sync-status label, projectname/petpiano sub-brains +
`project:projectname` boundary (visual mounts). Demo peer feeds are persistent fixtures that
NEVER enter the store.

whole prototype is disposable (`rm -rf <data_dir>/board3/`).

## What graduates later (WS-S3 / J1)

The **shell + feed** split is the durable architecture; real peers replace demo feeds
(same schema). The self exporter seeds the federation export surface (uuid + handle +
uuid-normalized relations already carried). Pending-changes graduate to real mutations
(promote → org-brain write, share → boundary membership, memo → the memo path, edit →
task update). Galaxies/boundaries become real membership sets. Liveness stays
per-machine (sync design reconciliation #5).

## Hard constraints honored

Additive only (new files + one subcommand); does not modify `write_board` /
`render_board.py` / `maybe_refresh_board`, the store schema, `lib/stream.py`, the
Tasktrail spec, or hooks. No store writes. No external assets (feeds via same-dir
`<script src>`; the `_EXTERNAL_NEEDLES` invariant is asserted for board3 output).
stdlib-only Python; vanilla JS/CSS. Reduced-motion respected across every animation
(CSS `@media` guard + a JS `REDUCE` flag gating physics/momentum/auto-rotate/pulses).
